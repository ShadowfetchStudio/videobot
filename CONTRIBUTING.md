# Contributing

Use Python 3.11+ and follow docs/DEVELOPMENT.md. Create a focused branch, add a regression test for each bug fix, and run lint, tests and a build before opening a PR. Keep download operations cancellable and preserve existing files. Never treat extension, MIME type or byte size alone as proof of valid media.

Use generated/local fixtures. Do not commit credentials, cookie files, signed URLs, queue databases or downloaded copyrighted media. Explain user-visible behavior, validation performed and limitations in the PR description. Feature changes should update README, changelog and relevant troubleshooting notes.
